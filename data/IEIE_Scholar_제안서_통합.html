3. 핵심 화면 분석

3.1 통합검색

  • 검색범위: 전체 · 제목 · 제목+초록 · 저자 · 키워드
  • 모드: 일반검색 / AI검색 / 에이전트검색 3중 구조
  • 상세검색: 최대 5개 조건, 필드(제목/저널/발행기관/저자), 주제, ISSN, 언어(한/영/중/일/기타), 원문보유 여부
  • 보조: 최근 검색어, 인기 검색어, 연도 필터
  • 약점: 전자공학 특화 facet(소사이어티, 기술분류, 학술대회 세션, 수상논문)이 없음. 수식·회로·코드 검색 불가.

3.2 논문 상세 (articleDetail)

영역 내용
기본정보 저자, 저널, 권호, 발행연도, 페이지, 이용수, 피인용수
액션 인용하기 · 내서재 담기 · 다운받기 · 공유 · 오류신고 · 논문보기 · AI뷰어보기
초록/키워드 섹션 앵커
AI 요약 한 줄 요약 + "연구방법" 표(배경·목적 / 대상·방법 / 분석·수행 / 결과·의의)
본문/목차 번역 선택 + 번역 버튼
참고문헌 / 피인용 자료 DBpia 자체 참조 데이터 기반(타 사이트와 상이 가능 고지)

3.3 권호 상세 (voisDetail)

  • 논문수 표시, 전체 선택 → 일괄 내서재 담기
  • 저널 내 검색, 이용기간 필터
  • 사이드바: 같은 발행기관의 저널 50종 나열(단순 목록), 추천논문/함께 다운받은 논문(종종 비어 있음)
  • 약점: 학술대회 논문집이 세션/트랙 구조 없이 평면 목록. 1,326편짜리 논문집을 탐색하기 매우 불편.

3.4 저널/발행기관 찾기

  • 자음·알파벳 필터 + 주제 트리. 발행기관명이 하이퍼링크가 아니어서 학회 단위 브랜드 페이지가 사실상 없음.

7. SWOT 요약

강점

  1. 520만 편 규모의 범용성, 대학 90% 구독의 유통망
  2. 2024~26 AI 기능 빠른 출시(에이전트·딥리서치·Reader)
  3. Citeasy로 글쓰기 워크플로우 장악
  4. citation_* 메타태그로 Google Scholar 유입 확보

약점 (= 우리 기회)

  1. 발행기관 브랜드 부재: 학회 페이지가 없고 저널이 평면 목록
  2. 학술대회 논문집 UX 열악: 1,000편+ 논문집이 세션 구조 없이 나열
  3. 저자 식별 미흡: ORCID 미연계, 동명이인 분리 불가, 저자 프로필 빈약
  4. 인용 네트워크 폐쇄적: 자체 범위 피인용만, Crossref/OpenAlex 미연동
  5. 도메인 무지: 수식·회로도·코드·데이터셋 검색/추출 없음
  6. 가격: 단건 9,000원, AI 유료화 예고 → 학회 회원 입장에서 "내 논문을 돈 주고 보는" 구조
  7. 개방성 부족: Open API가 서지 한정·신청제, 벌크 데이터는 유료 판매
  8. 커뮤니티 기능 사실상 사망(댓글 0건), 추천 패널 자주 비어 있음
  9. Citeasy macOS 미지원, 협업 기능 없음
  10. 페이지 로딩 시 빈 placeholder 다수(SSR 미흡), 저작권 표기 2022 등 유지보수 흔적

기회

  • 전자공학 특화 AI(수식/회로/표 이해, 영문 SCIE 저널 JSTS·SPC 연계)
  • 산업체(특별회원 골드/실버/브론즈) 대상 기술동향 B2B 상품

4. 콘텐츠 특성 (설계에 반영)

  1. 학술대회 비중이 압도적(60%+) → 세션/트랙/발표유형(구두·포스터)·수상(우수논문) 메타가 핵심. DBpia에는 이 구조가 없음.
  2. 한·영 혼재: 국내대회 한글, 국제대회·JSTS·SPC 영문 → 이중언어 검색·임베딩 필수.
  3. 반도체·회로 논문: 수식·회로도·표·측정 결과 중심 → 그림/표 추출과 멀티모달 검색이 차별점.
  4. 구 분과지 체계(SD/SP/SC/CI/TC/IE)가 현재 6개 소사이어티와 매핑 가능 → 통합 분류 축 설계.
  5. 저자 중복: 수십 년간 동명이인·소속 이동 → 저자 명확화(disambiguation) 엔진 필요(ORCID·KRI·소속·공저자 그래프).
  6. 학회 자체 자산: 웹진, 서울IT포럼 강연자료, 표준화백서, 해동 일본기술정보 → DBpia에 없는 독점 콘텐츠로 묶어 가치 상승.

2. 차별화 10대 전략

① 학술대회 중심 구조화 (DBpia 최대 약점 공략)

  • 논문집을 대회 → 트랙/소사이어티 → 세션 → 발표(구두/포스터) 트리로 제공
  • 세션 체어, 발표 시간, 발표 슬라이드/포스터 PDF, 우수논문상 배지
  • 대회 개최 전 "프로그램북 = 플랫폼" 으로 전환 → 참가자가 현장에서 플랫폼을 쓰게 만들어 트래픽을 학회 행사와 결합
  • 효과: 연 1,800편이 발표 당일 서비스 (DBpia는 수주~수개월 지연)

② 저자 아이덴티티 & 연구실 페이지

  • 저자 명확화 엔진(ORCID · KRI · 소속 · 공저자 그래프 · 이메일 도메인)
  • 저자 프로필: h-index(자체+OpenAlex), 연도별 발표, 소사이어티 활동, 수상, 공저자 네트워크 그래프
  • 연구실(Lab) 페이지: 교수 + 소속 학생 논문 자동 묶음, 대학원 진학 희망자·채용 기업의 핵심 탐색 경로
  • 저자 클레임(본인 인증) → 본인 논문 Open Access 전환·Preprint 업로드 권한

③ 인용 네트워크 개방 연동

  • Crossref · OpenAlex · Semantic Scholar · KCI 인용 데이터 통합 → DBpia의 "자체 범위 피인용" 한계 극복
  • 인용 문맥(citation context) 추출: "이 논문이 어떤 문장에서 인용됐는가"
  • 역방향: IEIE 논문이 IEEE/SCIE 논문에 인용된 경우 추적 → 학회 성과 홍보 자료 자동 생성

2. 파이프라인 단계

[1 수집] → [2 파싱] → [3 구조화] → [4 추출(Fig/Tab/Eq/Ref)] → [5 보강(DOI/인용/저자)] → [6 임베딩] → [7 색인] → [8 QA/검수]

단계 1. 수집 (ingest)

  • 입력: PDF + (있다면) 메타 CSV/XML(투고시스템 export)
  • R2 업로드 raw/{venue}/{year}/{file}.pdf, SHA-256 중복 제거, ingest_jobs 생성
  • 스캔본 판별: 텍스트 레이어 유무(pdfplumber) → OCR 큐 분기

단계 2. 파싱

도구 역할 비고
GROBID 헤더(제목·저자·소속·초록·키워드), 본문 섹션, 참고문헌 TEI 학술 PDF 표준, 한글 헤더 정확도 보완 필요
marker / Docling PDF→Markdown(레이아웃 보존), 표·수식(LaTeX) 추출 GROBID 보완
OCR 스캔본: Tesseract(kor+eng) 또는 Upstage Document OCR / Naver CLOVA OCR 한글 스캔 정확도는 상용 API가 유리
Claude (Haiku/Sonnet) 파싱 실패·저품질 헤더의 메타 재추출(첫 2쪽 → JSON), 한글 저자/소속 분리 비용: 2쪽 × 3만 편 ≈ 수십 달러

출력: papers(기본 메타), paper_sections, references_raw

단계 3. 구조화·정규화

  • 제목/초록 한·영 분리, 키워드 분리(;, ·, , 처리), 페이지 범위
  • 간행물 매핑: 파일명/폴더/메타 → venues, issues (50종 매핑 테이블)
  • 학술대회 세션 매핑: 프로그램북 파싱(표 추출) → sessions → 논문 제목 fuzzy 매칭(rapidfuzz ≥ 0.9)
  • 기술분류: Claude Haiku로 소사이어티/세부분류 다중 라벨 분류(few-shot + 학회 분류표) → subject_ids
  • 품질 플래그: 초록 없음, 저자 0명, 페이지 불일치 등 → 검수 큐

단계 4. Figure / Table / Equation 추출

  • PDFFigures2 또는 Docling 레이아웃 모델 → figure/table bbox + 캡션
  • 이미지 크롭(PyMuPDF) → R2 figures/{paper}/{n}.png (+ WebP 썸네일)
  • 표: Docling TableFormer → JSON 행렬 → paper_figures.extracted_data
  • 수식: marker LaTeX → chunk_type='equation'
  • 성능 지표 추출(★): 표 JSON + 캡션 → Claude Sonnet "metric/value/unit/condition" JSON → paper_specs (신뢰도 < 0.7은 미노출)

단계 5. 보강 (enrichment)

  1. DOI: 기존 DOI 조회(Crossref query.bibliographic) → 없으면 Crossref 회원 가입 후 신규 등록(XML 배치, 건당 $1 → 3만 편 약 $30k; 학술대회 논문은 선택적/논문지 우선)
  2. 참고문헌 매칭: references_raw.parsed → Crossref/OpenAlex 매칭 → 내부 논문이면 matched_paper_id → citations(source=internal)
  3. 피인용: Crossref cited-by, OpenAlex cited_by_api_url, KCI 인용 → citations 병합, papers.citation_count 갱신(일 1회)
  4. 저자 명확화(★ 핵심): - 블로킹: 성명 정규화(한글/로마자 변환 매핑, 공백·하이픈 제거) - 피처: 소속 유사도, 공저자 중복, 연도 근접, 이메일 도메인, 주제 벡터 유사도, ORCID/KRI 일치 - 모델: 규칙 + LightGBM 쌍분류 → 그래프 클러스터링(연결요소) - 임계값 ≥0.85 자동 병합, 0.6~0.85 검수 큐, 클레임 시 사용자 확정
  5. 기관 정규화: ROR 매칭 + 학회 소속 사전(대학 약칭·영문명)
  6. 코드/데이터셋 링크: 본문 URL 정규식(github.com, huggingface, ieee-dataport, zenodo) → HEAD 체크

단계 6. 임베딩

  • 청킹: 섹션 경계 우선, ~800토큰, 100토큰 오버랩, 표·캡션·수식은 독립 청크
  • 모델: voyage-3-large(다국어, 1024d) 또는 자체 호스팅 bge-m3(무료, 한글 양호)
  • 논문 대표 벡터: 제목+초록+키워드
  • 비용: 3만 편 × ~15k토큰 = 4.5억 토큰 → Voyage 기준 약 $50~100 (초기 1회)

단계 7. 색인

  • Postgres 트리거 → Typesense upsert(검색 필드 + facet), pgvector HNSW
  • ISR 재검증: 논문·권호·저자 페이지 revalidateTag

단계 8. AI 사전 생성 & QA

  • 요약 5종 배치 생성(Claude Batch API 50% 할인, 프롬프트 캐시) → paper_summaries
  • 자동 QA: 메타 완전성 점수, 참고문헌 파싱률, 샘플 100편 사람 검수 → 정확도 리포트
  • 관리자 교정 UI → 수정 이력 저장

-- 05. IEIE Scholar — PostgreSQL / Supabase 스키마 (v0.1)
-- 적용: supabase migration new init && 본 파일 복사 → supabase db push
-- 전제: extensions: pgvector, pg_trgm, unaccent, pgcrypto

create extension if not exists vector;
create extension if not exists pg_trgm;
create extension if not exists unaccent;
create extension if not exists pgcrypto;

-- =========================================================
-- 1. 분류·조직
-- =========================================================
create table societies (                       -- 6개 소사이어티
  id          smallserial primary key,
  code        text unique not null,            -- COMM, SEMI, COMP, AISP, SYSC, INDE
  name_ko     text not null,
  name_en     text not null
);

create table subject_codes (                   -- 세부 기술분류(학회 자체 + IEEE 분류 매핑)
  id          serial primary key,
  parent_id   int references subject_codes(id),
  code        text unique not null,
  name_ko     text not null,
  name_en     text,
  society_id  smallint references societies(id),
  legacy_division text                         -- SD/SP/SC/CI/TC/IE 매핑
);

create table organizations (                   -- 대학·기업·연구소 (소속 정규화)
  id          serial primary key,
  name_ko     text not null,
  name_en     text,
  ror_id      text,                            -- Research Organization Registry
  domain      text,                            -- 이메일 도메인
  type        text check (type in ('university','company','institute','government','other')),
  country     text default 'KR'
);
create index on organizations using gin (name_ko gin_trgm_ops);

-- =========================================================
-- 2. 간행물·권호·학술대회
-- =========================================================
create table venues (                          -- 저널/학술대회 시리즈 (50종)
  id          serial primary key,
  slug        text unique not null,            -- j-ieie, jsts, spc, conf-summer, iceic ...
  title_ko    text not null,
  title_en    text,
  venue_type  text not null check (venue_type in ('journal','journal_legacy','conference_domestic','conference_intl','magazine','education','report')),
  issn_print  text,
  issn_online text,
  publisher   text default '대한전자공학회',
  indexing    text[],                          -- {'SCIE','SCOPUS','KCI'}
  active      boolean default true,
  successor_id int references venues(id),      -- 분과지 → 통합지
  description text
);

create table issues (                          -- 권호 / 학술대회 1회차
  id          serial primary key,
  venue_id    int not null references venues(id),
  volume      text,
  number      text,
  year        smallint not null,
  month       smallint,
  title       text,                            -- '2025년도 하계학술대회 논문집'
  event_start date,
  event_end   date,
  location    text,
  cover_url   text,
  paper_count int default 0,
  unique (venue_id, volume, number, year)
);

create table sessions (                        -- 학술대회 세션/트랙 (DBpia에 없는 구조)
  id          serial primary key,
  issue_id    int not null references issues(id) on delete cascade,
  society_id  smallint references societies(id),
  track       text,                            -- '반도체 소자', 'AI 신호처리'
  code        text,                            -- 'SD-3'
  title       text not null,
  chair       text,
  room        text,
  start_at    timestamptz,
  end_at      timestamptz,
  type        text check (type in ('oral','poster','invited','keynote','tutorial','panel'))
);

-- =========================================================
-- 3. 논문 (핵심)
-- =========================================================
create table papers (
  id              bigserial primary key,

create or replace function papers_tsv_update() returns trigger language plpgsql as $$
begin
  new.search_vector :=
    setweight(to_tsvector('simple', coalesce(new.title_ko,'') || ' ' || coalesce(new.title_en,'')), 'A') ||
    setweight(to_tsvector('simple', array_to_string(coalesce(new.keywords_ko,'{}'),' ') || ' ' || array_to_string(coalesce(new.keywords_en,'{}'),' ')), 'B') ||
    setweight(to_tsvector('simple', coalesce(new.abstract_ko,'') || ' ' || coalesce(new.abstract_en,'')), 'C');
  new.updated_at := now();
  return new;
end $$;

create or replace function can_access_fulltext(p_user uuid, p_paper bigint)
returns boolean language sql stable as $$
  select exists (select 1 from papers p where p.id = p_paper and p.oa_status in ('diamond','gold','green'))
      or exists (select 1 from profiles pr where pr.user_id = p_user and pr.role in ('member','editor','admin') and (pr.member_valid_until is null or pr.member_valid_until >= current_date))
      or exists (select 1 from subscriptions s where s.user_id = p_user and s.status='active' and s.period_end > now())
      or exists (select 1 from purchases pu where pu.user_id = p_user and pu.paper_id = p_paper)
      or exists (select 1 from profiles pr join institutions i on i.org_id = pr.org_id
                 where pr.user_id = p_user and i.valid_until >= current_date);
$$;
